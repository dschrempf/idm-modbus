# A write interface that makes the EEPROM cost visible

## The question

The package read and set the user level, and nothing else. A consumer that
manages the heat pump needs writes: the requests 1710, 1712 and 1713, the PV
surplus at 74, and now and then an operating mode or setpoint. `CLAUDE.md`
kept writing out until an interface made the cost of an EEPROM write visible
rather than leaving it to an extra argument.

## Outcome, 2026-11-05

Built, tests passing, not yet tried on the machine.

- `IDM.Modbus.TCP`: function codes 6 and 16 (812170 §4.5 writes a `FLOAT`
  with 16, a `UCHAR` or `BOOL` with 6), the echo checked, `UnexpectedEcho`.
- `IDM.Navigator.Register`: `encode`, the inverse of `asWritten`, to
  `NonEmpty Word16`; `Refusal`; the kind `Cost = Free | EepromCycle` with
  `costOf` (unknown persistence is `EepromCycle`) and its singleton `SCost`.
- `IDM.Navigator.Target`, generated by `tools/transcribe.py` from the
  hand-written `data/navigator-2.0-targets.tsv` (address, English constructor
  name; the Haddock quotes the German name). Only listed registers are
  targets — "active" — and listing one goes with testing it on the machine,
  so there is no separate tested/untested category. The one target is 74
  `PvSurplus`. `targetRegister` takes each register by a typed splice,
  `registerOf`, that fails the build where the table and the generated cost
  disagree, so the lookup is total and the TSV is not parsed twice.
- `IDM.Navigator.Write`: `write :: … -> Target c -> Value -> IO (Outcome
  c)`. An EEPROM write reads first and compares bytes, sending nothing when
  they match (`Unchanged`, the manual's "bei Wertänderungen"); a volatile
  write always sends. Every readable target is read back: `Confirmed`,
  `DidNotStick`, `Unconfirmed` for write-only, `ReadBackFailed`. No budget
  and no counting hook: a consumer counts `Sent` at `'EepromCycle`.
- `idm-write HOST ADDRESS VALUE [--eeprom]`: an EEPROM target is refused,
  unsent, without `--eeprom`.

Decided along the way:

- A confirmation says the register stored the value; whether the controller
  acts on it is the consumer's concern.
- 1999 `Störmeldungen quittieren` stays eligible as a target like any other.
- 1230 and 1231, both printed `Kaskade / Bivalenzpunkt Warmwasser`, are to be
  named by address when activated.
- Not built, as nothing active needs them:
  `targets-for-heating-circuits-and-zone-modules` and
  `target-values-typed-per-register`.

What the interface cannot settle stays with session 6 of
`run-the-open-todos-in-six-sessions`: writing while a second Modbus client
polls, and `controller-behavior-when-glt-values-stop-unknown`.
