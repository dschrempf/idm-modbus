# Table transcription: what `tools/transcribe.py` reads, refuses and writes

Read before running or changing `tools/transcribe.py`, adding a target, or
regenerating the register table for a new revision of the manual or a new
software of the controller.

## Targets

The targets, the registers a write may go to, are a hand-written list,
`data/navigator-10-targets.tsv`: an address and an English constructor name
each. Only listed registers can be written, and listing one goes with trying
on the machine that a write to it takes effect. The script refuses an address
the table lacks or nothing may write, a write-only register whose write costs
an EEPROM cycle, and a member of a heating circuit or zone module family,
which would need the circuit or module as an argument and is not generated
yet. The cost of a write, `'Free` or `'EepromCycle`, is derived from the row;
`targetCost` takes it from the table through `$(costAt …)`, so the build fails
where a constructor's type and the table disagree, and `$$(registerOf …)`
repeats the script's refusals.

## The `observed` column and the scan

Given a scan, `captures/navigator-10-scan-*.json`, the script fills the
`observed` column from what one machine answered; without one it carries the
column over from the table it replaces, so the table can be regenerated by
someone who does not have the scan.

The scan holds no transcribed data of its own: `idm-dump --json` writes it,
and it records only address, status, exception code, raw bytes and the
uninterpreted number, so a correction to the table cannot leave it saying
something else. The bytes and the number of the myiDM identifier,
`myIdmAddress`, are redacted, as in a webapi capture. A defect in a register
name, unit or range is therefore a defect in the transcription script, not in
the Haskell parser.

## Rows from `N2_GLTMON`

The rows of the `source` `gltmon` come the same way: the controller's web page
`N2_GLTMON` lists addresses the manual does not, and given a webapi capture
holding that page and a widths capture of those addresses, the script adds
them, with the width measured and everything the page does not state left
unstated; without the two it carries them over. Where the manual prints an
address the page lists too, the manual's row stands, unless the width
measured contradicts its datatype, as at 1072; then it goes even where the
page names nothing to put in its place, as at 4112.

Their parameter identifier is the one input written by hand,
`data/navigator-10-gltmon-parameters.tsv`: the page names no identifier and
the settings tree no address, so only moving a setting and watching which
register follows can join them. The script reads that file in either case
and, given the webapi capture, refuses a join the capture contradicts.

## Codes the manual does not print

A code of an enumeration measured on the machine is the third hand-written
input, `data/navigator-10-measured-enums.tsv`: address, code, label, and the
document in `doc/` that holds the evidence. The script adds the codes to the
enumerations and widens the register's range to a code outside it, so 1005
reads -1 to 5 and its `ffff`, "Aus", decodes as a value. It refuses an
address the table lacks, a code already labeled, which a revision printing it
makes redundant, evidence that is no file, and a register with no range. A
row carries no software: like the manual's, its fact is taken to hold until
a measurement says otherwise. A fact that is not a code, such as 1104 not
following M73, stays prose in `doc/`.

The `scale` column, `magnitude` or `enumeration`, is derived from the labels:
a labeled register is an enumeration, but for a `BOOL` and a percentage,
whose labels mark points of its scale, as at 1104. `decode` gives an
enumeration a `Code` rather than a `Count`.

## Software

The script reads `data/navigator-10-software.tsv` and refuses a capture
recorded on another software. The file states series, major, minor and patch
by hand, `unknown` where a part was never read.

## Reading the manual

`manual/` holds the manufacturer's PDFs, which the script reads, and is
ignored by git. The table is read from 812663 rev. 0, the Navigator 10's
manual; given 812170 rev. 12 instead, the script writes the same files but
for the 110 rows of rooms 7 to 9 and their enumerations. The list is printed
inconsistently — the same column appears in a different order on different
pages — so cells are read by the column they are printed in, taken from the
page heading, not by the order they appear in. From revision 12 on a remark
may follow a name on the next line, and only its smaller type tells it from
a name that wraps, so the script reads the type's height off the PDF too.
812663 prints a thumb index, 9 to 13, at the edge of every page, which the
layout text sets into the rows beside it; the script crops the page to the
type area, `TYPE_AREA`, before reading either view.
